# Bog Music

Музыкальный плеер PWA: https://b-on-g.github.io/music/. Файлы песен лежат на
самом устройстве (OPFS), фонотека (названия, плейлисты, настройки) синкается
через [Giper Baza](https://github.com/giper-dev/baza). Файлы между устройствами
переносятся напрямую по WebRTC.

## Что умеет

- Поиск и скачивание с YouTube (сервер `srv/tube`), прослушивание превью стримом.
- Приём музыки из Телеграма: пересланное боту приезжает в «Мою музыку».
- Скробблинг прослушанного в last.fm.
- Загрузка аудиофайлов с устройства.
- Плейлисты: основной, архив, свои списки, принятые шары (`shared:<имя>`).
- Ручная сортировка drag'n'drop, перенос в архив, удаление.
- Плеер: повтор одного/всех, shuffle без повторов, «Моя волна» ($bog_recsys),
  громкость, эквалайзер, восстановление последней сессии.
- Выравнивание громкости по EBU R128, персональный обрез трека.
- Перенос файлов между своими устройствами: устройство без файла видит, на каком
  устройстве он лежит, и забирает его оттуда напрямую.
- Одноразовая ссылка другу: треки идут напрямую от отправителя к получателю.
- Перенос аккаунта на другое устройство ссылкой `#account=<key>`.
- Выгрузка видимого плейлиста zip-архивом.

## Почему файлы не в Базе

Ленд в Базе после первого чтения живёт в памяти до конца сессии, а каждый трек
раньше был своим лендом: фонотека оседала в куче. Ещё База не умеет удалять,
и мастер на маленьком боксе копил байты всех пользователей. Поэтому в Базе
только метаданные, а байты — на устройстве. С Базой не боремся: никаких подмен
её классов и выгрузки чанков.

## Модель данных

| Модуль | Класс | Что это |
|---|---|---|
| `account/` | `$bog_music_account_baza` | Home land: профиль, треки, плейлисты, устройства, сигналы WebRTC, вся CRUD-логика |
| `track/baza/` | `$bog_music_track_baza` | Трек: метаданные, `Holders` — id устройств, где лежит файл |
| `device/` | `$bog_music_device`, `$bog_music_device_baza` | Id устройства (localStorage), имя по User-Agent, отметка «на связи» |
| `share/` | `$bog_music_share_baza` | Ленд одноразовой ссылки: зашифрованные имя отправителя, приглашение и ответ |

Ключ трека — строка `0_<fnv-хеш источника>`: `yt:<id>`, `tg:<file_unique_id>`,
имя+размер+дата для файла с устройства. Ключ же — имя файла в OPFS.

Где файл для текущего устройства (`account.place(key)`):

- `disk` — в OPFS здесь;
- `remote` — в `Holders` есть другое устройство: строка показывает «на «iPhone»»,
  в меню трека и в плеере — «Перенести»;
- `lost` — нигде.

## Модули

- `disk/` — `$bog_music_disk`: OPFS-папка `bog_music`, `put/file/drop/keys`,
  чтение диапазона, реактивный `has(key)`. Запись через `createWritable`, где его
  нет (старый Safari) — через `createSyncAccessHandle` во временном воркере.
- `stream/` — `$bog_music_stream`: сервис-воркер отдаёт `<audio>` адрес
  `bog-music-stream?key=` с HTTP Range прямо из OPFS (если OPFS в воркере нет —
  спрашивает страницу). Стабильный адрес нужен iOS: автопереход на следующий
  трек обязан звать `play()` синхронно в `ended`.
- `peer/` — `$bog_music_peer`: WebRTC без trickle ICE (SDP целиком после сбора
  кандидатов), передача файлов по DataChannel кусками по 16 КБ с учётом
  `bufferedAmount`. Протокол: `list`, на каждый файл `file` + куски + `end`,
  `done`, ответ `ack`.
- `beam/` — `$bog_music_beam`: перенос между своими устройствами (см. ниже).
- `share/` — `$bog_music_share`: выбор треков и одноразовая ссылка (см. ниже).
- `app/` — страницы, очередь, загрузка файлов, дев-режим (вкладка журнала по галке в аккаунте), плашка
  «N треков только на «iPhone» — Перенести сюда».
- `player/` — плеер, только свой `<audio>`; цепочка `<audio> → gain → limiter`.
- `gain/`, `eq/`, `scrobble/`, `tube/`, `tg/`, `code/`, `zip/`, `log/` — как были.
- `landing/` — лёгкий бандл-лендинг для поиска, пререндерится в деплое.

## Перенос между своими устройствами

У всех устройств одного аккаунта один home land, он и служит сигнальным каналом.

```
каждые 30 с: Devices[<id>] = { Name, Beat }        ← «на связи», если Beat < 90 с
B хочет файлы с A:
  B: offer → Signals['offer:B>A'] = { at, sdp }
  A (опрос каждые 2 с) видит свежий offer → answer → Signals['answer:A>B']
  B ждёт answer до 60 с → DataChannel → { type: 'want', keys }
  A отдаёт файлы → B пишет в OPFS и добавляет себя в Holders
```

Оба устройства должны быть с открытым приложением. STUN — Google и Cloudflare,
своего TURN нет: за симметричным NAT (часть мобильных операторов) соединение
может не собраться.

## Одноразовая ссылка

```
Отправитель: треки на диске → AES-ключ → новый ленд
  [null: read, burn: post] с Kind='p2p1', Sender (шифр), Count
  ссылка #share=<land>.<aes>.<burn>; ленд запоминается в localStorage
  bog_music_shares_open (живёт 7 дней)
Получатель: читает ленд → Done? «использована» → offer, шифрует, пишет Offer
  ключом burn → ждёт Answer до 5 минут
Отправитель (опрос каждые 3 с): видит Offer → сразу убирает ссылку из открытых,
  пишет Answer и Done=true → отдаёт файлы
Получатель: файлы в OPFS, треки в плейлист shared:<имя>
```

Ссылка сгорает в момент ответа: оборвалась передача — нужна новая ссылка.
Отправитель должен открыть приложение, пока получатель ждёт.

## Инфраструктура

- **Сервер приложения**: один процесс на `tube.87.120.36.150.ip.giper.dev`
  (`srv/deploy/`), в нём три набора маршрутов: `tube` (yt-dlp), `tg`
  (телеграм-бот), `fm` (скробблинг). Второй node на бокс не ставим: там 1 CPU и
  ~960МБ на всё вместе с baza. Переменные окружения — в `srv/deploy/compose.yml`,
  секреты на боксе в `.env` рядом с ним. Бандл смонтирован томом, а не запечён в
  образ (диск под завязку, пересборка гоняет apt с ffmpeg): обновление = scp
  `node.js` в `/root/tube/` + `docker compose up -d --force-recreate`. Без
  `--force-recreate` контейнер продолжает читать старый inode примонтированного
  файла и код не обновляется.
- **Серверный бандл держать чистым от браузерного кода.** mam подключает к
  модулю его родителя, поэтому серверные половины лежат в `srv/`, а не рядом с
  клиентами: иначе в node-бандл затягивает `$mol_fetch`/`$mol_state_local`, а
  те тянут jsdom, которого в образе нет — контейнер падает на старте.
- **Baza master**: только свой узел `https://cmyser-bg-pony.87.120.36.150.ip.giper.dev/`,
  на localhost — `http://localhost:9090/`. Список мастеров заменяется целиком в
  `app/app.view.ts`.
- **Deploy**: GitHub Actions (`.github/workflows/deploy.yml`) — gh-pages; ветки
  уезжают превью в `branch/<имя>/`.
- **Билд**: из корня MAM — `npx mam bog/music/app` (приложение) и
  `npx mam bog/music/srv/tube` (сервер), артефакты в `-/`.
- **Dev**: `http://localhost:9080/bog/music/app/-/test.html`.

## Известные ограничения

- Физического удаления в Базе нет: «удаление» трека — `cut` из словаря.
- Перенос файла требует, чтобы оба устройства были открыты одновременно.
- Без своего TURN часть пар устройств не соединится.
- Safari может чистить хранилище сайта, которым не пользовались 7 дней;
  установленное на экран PWA, по документации, под это не попадает — проверяется.
- Громкость выравнивается только у скачанных треков, стрим превью не меряется.
